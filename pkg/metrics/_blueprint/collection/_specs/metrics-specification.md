# ProofBox Metrics Specification

This document provides the authoritative specification for ProofBox metrics implementation.

## Metric Naming Convention

All metrics follow Prometheus naming conventions:
- Prefix: `jmt_` (Jellyfish Merkle Tree)
- Units in metric name (e.g., `_seconds`, `_bytes`)
- Total suffix for counters (e.g., `_total`)
- Snake case naming

## Metric Definitions

### Counters

| Metric | Labels | Description | Implementation Status |
|--------|--------|-------------|----------------------|
| `jmt_commits_total` | none | Total number of successful commits | ✅ Implemented |
| `jmt_operations_total` | type={insert, update, delete, lookup_hit, lookup_miss} | Operations by type | ✅ Implemented (updates tracked as inserts) |
| `jmt_proof_generations_total` | type={inclusion, exclusion} | Proofs generated by type | ⏳ Pending |
| `jmt_hash_operations_total` | none | Total hash computations | ⏳ Pending |
| `jmt_db_reads_total` | none | Database read operations | ✅ Implemented |
| `jmt_db_writes_total` | none | Database write operations | ✅ Implemented |
| `jmt_errors_total` | type={storage, validation, codec, version, commit, batch} | Errors by category | ✅ Implemented |
| `jmt_validation_failures_total` | none | Proof validation failures | ⏳ Pending |

### Histograms

| Metric | Buckets | Description | Implementation Status |
|--------|---------|-------------|----------------------|
| `jmt_commit_latency_seconds` | 0.0001 to 3.2s (exponential) | Time to commit a version | ✅ Implemented |
| `jmt_lookup_latency_seconds` | 0.0001 to 0.4s (exponential) | Time to lookup a key | ✅ Implemented |
| `jmt_proof_generation_latency_seconds` | 0.0001 to 0.8s (exponential) | Time to generate proof | ⏳ Pending |
| `jmt_batch_size` | 1, 5, 10, 25, 50, 100, 250, 500, 1000, 2500, 5000, 10000 | Nodes per batch | ✅ Implemented* |
| `jmt_proof_size_bytes` | 64B to 256KB (exponential) | Size of generated proofs | ⏳ Pending |

*Note: Currently tracks nodes created, not operation count

### Gauges

| Metric | Description | Implementation Status |
|--------|-------------|----------------------|
| `jmt_tree_height` | Current maximum tree depth | ⏳ Pending |
| `jmt_tree_nodes_total` | Total nodes in current version | ✅ Implemented |
| `jmt_versions_stored` | Number of versions retained | ✅ Implemented |
| `jmt_db_live_bytes` | Storage size in bytes | ⏳ Pending |

## Error Categories

Fixed set to prevent cardinality explosion:
- `storage`: Database/storage layer errors
- `validation`: Input validation failures
- `codec`: Encoding/decoding errors
- `version`: Version not found or invalid
- `commit`: Commit operation failures
- `batch`: Batch operation failures

## Performance Requirements

- **Overhead**: < 10% when enabled (typically ~1%)
- **Memory**: Minimal, proportional to unique label combinations
- **Thread Safety**: All operations must be thread-safe

## Integration Points

### Tree Operations
1. **Put/Delete**: Record operation type and errors
2. **Get**: Record lookup latency and hit/miss
3. **CommitVersion**: Record commit metrics, batch size, DB writes

### Storage Operations
1. **Node Load**: Record DB read
2. **Node Save**: Record DB write
3. **Value Load/Save**: Record DB operations

### Error Paths
All error returns should record appropriate error metric before returning.

## Testing Requirements

1. **Accuracy Tests**: Verify exact metric values
2. **Concurrency Tests**: Ensure thread safety
3. **Performance Tests**: Validate overhead targets
4. **Integration Tests**: Verify metrics are recorded

## Future Enhancements

1. **Proof Metrics**: Implement when proof generation is added
2. **Hash Metrics**: Track when cryptographic operations are implemented
3. **Tree Height**: Calculate efficiently during updates
4. **Storage Size**: Integrate with storage backend
5. **Update Tracking**: Distinguish updates from inserts in batches

## Usage Guidelines

### Production Setup
```yaml
# Prometheus scrape config
scrape_configs:
  - job_name: 'proofbox'
    scrape_interval: 15s
    static_configs:
      - targets: ['localhost:9090']
```

### Grafana Dashboard
Key panels to include:
- Request rate by operation type
- Error rate by category
- P50/P95/P99 latencies
- Tree growth over time
- Storage I/O rates

### Alerting Rules
```yaml
groups:
  - name: proofbox
    rules:
      - alert: HighErrorRate
        expr: rate(jmt_errors_total[5m]) > 0.01
      - alert: HighCommitLatency
        expr: histogram_quantile(0.99, jmt_commit_latency_seconds) > 1
```
